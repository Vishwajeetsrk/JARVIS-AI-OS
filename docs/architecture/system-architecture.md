# System Architecture — Vishwajeet AI Operating System ("Jarvis")

## Executive Summary
Vishwajeet's **AI Operating System ("Jarvis")** is a production-grade, dual-layer multi-agent platform designed to take software products from concept to launch, monitoring, and scaling across Learnify AI, AgencyOS, DreamSync, SkillForge, and freelance client engineering work.

## Layer 1: Prompted In-Conversation Reasoning Layer (Phase 0 Baseline)

### How It Operates
In Layer 1, "Jarvis" is an organized prompting and reasoning framework executing inside a live chat conversation with Claude.
1. **Request Activation**: When a new request arrives (e.g., *"let's add a subscription upgrade flow to AgencyOS"*), Claude evaluates the request against all 13 skill frontmatter `description` fields.
2. **CEO Validation**: `ceo-agent` activates first, reads `~/.agent-memory/global/` to review past mistakes, and runs the **Clarity Framework** (Revenue potential, Real users, Recurring model, Niche fit).
3. **Golden Flow Sequence**: Upon issuing a **GO** decision, `ceo-agent` routes execution sequentially:
   - `team-agent` -> Task breakdown & status update.
   - `saas-builder` -> PRD, architecture, & security plan (referencing `stack-notes.md`).
   - `design-agent` -> Brand sheet check & UI token application.
   - `test-agent` -> Independent security checklist sign-off (no self-certification permitted).
   - `devops-agent` -> Deployment build & rollback snapshot tagging.
   - `memory-agent` -> Writes lessons learned back to `~/.agent-memory/global/`.

---

## Layer 2: Orchestration, Business-Ops & Sandboxed Coding (Phase 1-2 Upgrade)

### How It Operates
Layer 2 turns the prompted reasoning sequence into an automated, background-capable service operating outside live chat windows.
1. **Mastra TS Orchestrator** (`src/mastra/`): Graph-based TypeScript workflow engine executing agent sequences on cron schedules, webhooks, or API calls without needing an active chat window.
2. **n8n Webhook Bridge** (`n8n-bridge.ts`): Handles pure trigger-to-action business operations (e.g., Razorpay payment webhooks, automated invoice delivery) independently of LLM reasoning.
3. **OpenHands Docker Sandbox** (`openhands-runner.ts`): Sandboxed container execution environment implementing well-specified, test-gated coding tasks without manual user typing.
4. **Mandatory Security Gate** (`test-agent-pr-gate.ts`): Code generated by OpenHands is strictly gated by `test-agent` secret detection and Zod schema checks before merging.

## Skill Matching & Trigger Mechanics

- **Frontmatter Description Matching**: Each `SKILL.md` contains a frontmatter `description` loaded with explicit trigger keywords (e.g. *"Trigger this whenever the user wants brand guidelines..."*).
- **Semantic Inference vs. Explicit Invocation**: Claude semantically compares user requests against descriptions. Explicitly naming a skill (*"use design-agent for this"*) guarantees 100% deterministic matching.
- **Ordered Handoffs**: Multi-skill matches are ordered according to `ceo-agent`'s explicit Golden Flow routing rules.
